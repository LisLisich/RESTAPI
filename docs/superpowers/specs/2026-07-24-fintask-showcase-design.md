# FinTask Showcase Design

## Цель

Подготовить публичный showcase-релиз Go backend-проекта для собеседований на
позицию Junior Go Backend Developer с фокусом на финансовые системы.

## Архитектура

FinTask остается модульным монолитом с feature-модулями `identity`, `tasks`,
`wallet`, `payments` и `notifications`. HTTP-слой вызывает service, service
зависит от repository/provider interfaces, PostgreSQL adapters владеют SQL и
маппингом ошибок.

React использует серверные cookie-сессии. Учебный CLI использует короткий
Ed25519 JWT и ротируемый refresh token. Google login реализуется через
Authorization Code + PKCE/OIDC.

Финансовая истина хранится в PostgreSQL. Суммы представлены целым количеством
копеек. Успешный webhook YooKassa одной транзакцией меняет платеж, добавляет
сбалансированные ledger entries и создает outbox event.

## Инварианты

- Пароли никогда не сохраняются и не логируются в исходном виде.
- Сессионные и refresh tokens хранятся только как хеши.
- Пользователь читает и изменяет только собственные ресурсы.
- `Money` не использует `float`.
- Сумма ledger entries одной транзакции равна нулю.
- Один provider payment зачисляется не более одного раза.
- Ошибка SMTP не откатывает подтвержденное зачисление.
- Открытый `/api/v1` недоступен в production.

## Границы релиза

- Валюта только RUB.
- YooKassa работает только в sandbox.
- Нет возвратов, переводов, вывода, MFA, Kafka и административных ролей.
- SMTP имеет at-least-once семантику.
- Старые users/tasks сохраняются как legacy-данные без account.
